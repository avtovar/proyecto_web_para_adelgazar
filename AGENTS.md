# AGENTS.md — Método para Adelgazar

## Repo facts

**Stack:** Node.js + Express · PostgreSQL (Neon/Vercel Postgres) · Vanilla HTML/CSS/JS · JWT · Vercel · Capacitor (Android)

**Entrypoints:**
- `api/index.js` — Express app (used by both local dev & Vercel serverless)
- `api/db.js` — PostgreSQL data layer; auto-creates tables (`usuarios`, `peso_semanal`, `sesiones`) on first query — **no migration files**
- `server.js` — Local dev server (wraps api/index.js + static files from `public/`)
- `public/index.html` — SPA frontend; all logic in `public/script.js`
- Vercel: `vercel.json` routes all traffic to `api/index.js` as serverless function

**Commands:**
- `npm run dev` / `npm start` — starts local server on port 3000
- `npm run build:android` — `npx cap sync android && npx cap open android`

**Auth:**
- JWT in HttpOnly cookie (primary) + Bearer header fallback (for mobile)
- Token stored in `localStorage` on login; cookie set by server
- Password: PBKDF2 (SHA-512, 100k iterations), stored as `salt:hash`
- Rate limit: 200 req/15min global on `/api/`, 10 req/15min on login & register
- CORS whitelist includes localhost, capacitor://, ionic://, plus `CORS_ORIGIN` env var

**Database:**
- Tables: `usuarios`, `peso_semanal`, `sesiones` with `ON DELETE CASCADE` foreign keys
- `sslmode=no-verify` forced for Neon compatibility
- `POSTGRES_URL` env var (or `DATABASE_URL` fallback)

**Environments:**
- `.env.example` — copy to `.env`, set `POSTGRES_URL`, `JWT_SECRET` (autogenerated if missing), `PORT`
- `NODE_ENV=production` enables secure cookies
- Auth mode uses env `CORS_ORIGIN` for additional origins (comma-separated)

**Edge cases & constraints:**
- Weight validation: 40–250 kg, age ≥ 18 years
- 6 weight ranges for exercises: `40-79`, `80-99`, `100-120`, `121-140`, `141-150`, `151-250`
- 5 exercises with weights + 5 without per range; `videoId` optional (YouTube embed modal)
- SVG weight chart rendered client-side; no chart library
- Frontend uses `escHtml()` / `escapeHtml()` helpers — no templating library
- No test framework is configured

**Android (Capacitor):**
- App ID: `com.metodo.adelgazar`, webDir: `public`
- API calls use `API_BASE_URL = 'https://metodoparaadelgazar.vercel.app'` in `script.js`
- JWT via Bearer header (cookies not available in WebView)

## Web design reference guide

### 1. Responsive design (CSS + HTML)
- Use CSS Grid + Flexbox, no framework
- `clamp()` for fluid typography, `min()`/`max()` for containers
- Mobile-first media queries at 880px and 560px breakpoints
- `img`, `iframe`, `svg` should be `max-width: 100%` intrinsically
- Touch targets ≥ 44px (already enforced in this repo)

### 2. Usability checklist
- Forms: clear labels, `autocomplete` attributes, `aria-live="polite"` on messages
- Loading states on buttons (disabled + "Cargando...") — pattern: `setLoading(btnId, bool)`
- Keyboard: Escape closes modals, focus management on open/close
- Error messages inline, not in alerts; color-coded (`.error` / `.success`)
- Touch: min 44px targets, adequate tap spacing

### 3. Redesign workflow
1. Audit current state (analytics, user feedback, performance)
2. Define scope (pages, features, content)
3. Wireframe → mockup → prototype (Figma or code)
4. Develop component by component (atomic design)
5. QA: cross-browser, responsive, a11y, performance
6. Deploy to staging, A/B test if possible
7. Launch (Vercel deploy = `git push` to `main`)

### 4. E-commerce mockups
- Product cards: image, name, price, CTA, rating
- Grid layout with filter/sort sidebar
- Checkout steps: cart → shipping → payment → confirmation
- Cart: line items, totals, quantity controls, remove
- Mobile: sticky bottom cart summary

### 5. Multimedia + performance
- Lazy-load images and iframes (`loading="lazy"`)
- YouTube embeds: use `poster` placeholder, load iframe on user click (modal pattern in this repo)
- `<picture>` for responsive images with WebP
- Video wrapper with `padding-bottom: 56.25%` for 16:9 aspect ratio
- `compression()` middleware (enabled), minimize JS/CSS, use system fonts

### 6. SEO
- Semantic HTML: `<main>`, `<section>`, `<article>`, `<header>`, `<nav>`
- One `<h1>` per page, hierarchical headings
- Meta description, `lang` attribute, Open Graph tags
- Alt text on all images (SVG charts: `role="img"` + `aria-label`)
- Vercel sitemap generation, clean URLs, `robots.txt`

### 7. Landing page (lead gen)
- Above-fold: headline, subheading, CTA button
- Social proof (badges, testimonials, numbers)
- Feature highlights with icons
- Form: minimal fields (email + name), clear value prop
- Trust signals: privacy note, security badges
- Thank-you page or inline confirmation

### 8. Accessibility
- Semantic HTML structure
- All interactive elements keyboard-accessible
- `aria-label`, `aria-live="polite"` for dynamic content
- `[hidden]` attribute for show/hide (not just display:none)
- Color contrast ratios ≥ 4.5:1 (test with tools)
- Focus indicators visible; `prefers-reduced-motion` respected
- Forms: `<label>` + `for`/`id` pairing, error announcements

### 9. Maintenance plan
- Weekly: check Vercel dashboard, monitor errors, review DB size
- Monthly: update dependencies (`npm outdated` → `npm update`), audit security
- Quarterly: content refresh (exercises, static pages), performance audit
- Continuous: monitor Neon DB connections, rate limit efficacy
- Backup: PostgreSQL periodic snapshots (Neon automatic)

### 10. Web analytics
- Integrate privacy-focused analytics (Plausible, Umami, or custom)
- Track: page views, registrations, weight entries, exercise views, video plays
- Use data to inform: exercise catalog changes, UX flow improvements
- Analytics script: async, non-blocking, no cookie consent required (privacy-first)

### 11. Industry templates
- **Hospitality:** Hero with booking widget, amenities grid, gallery carousel, reviews, location map
- **Services:** Service cards with pricing, testimonials, contact form, portfolio/projects
- **Retail:** Product grid, category nav, cart, checkout, search
- All: responsive, semantic, optimized Core Web Vitals

### 12. Mobile-first approach
- Design for smallest screen first, then `min-width` breakpoints
- Content hierarchy: what matters most on mobile
- Touch: 44px minimum tap targets, 8px spacing
- Forms: `type="email"`, `inputmode="numeric"`, `autocomplete`
- Test on real devices, not just emulator
- This repo: breakpoints at 880px (single column) and 560px (stack headers)

### 13. User testing
1. Define test tasks (e.g., "register, log weight, find exercise video")
2. Recruit 5 users per round (NN/g rule)
3. Think-aloud protocol, record screen + audio
4. Measure: task completion, time on task, errors, satisfaction
5. Identify top 3 pain points → prioritize fixes
6. Iterate: fix → retest with new users
7. Remote tools: Lookback, Maze, or manual video calls

### 14. Color theory
- Pick primary (action), accent (highlights), neutral (backgrounds/text)
- Use HSL for systematic color scales
- Ensure WCAG contrast ratios: 4.5:1 text, 3:1 large text
- Test with color blindness simulators (Coblis, Chrome DevTools)
- This repo palette: green (#1f7a5a) primary, orange (#c46a2b) accent, warm neutrals

### 15. Multi-project management
- One repo per project, monorepo only if shared modules
- Use GitHub Projects / Issues for task tracking
- Branch strategy: `main` (production), feature branches, PRs
- CI/CD: Vercel auto-deploys on `git push` to `main`
- Prioritize: maintenance → bug fixes → features → experimentation

### 16. Advanced CSS
- Custom properties (`:root` variables) for theming
- `clamp()`, `min()`, `max()` for fluid layouts
- Grid: `auto-fit`/`auto-fill` with `minmax()` for responsive columns
- Transitions/animations: `@keyframes`, `transition`, `transform`
- Focus-within, `:has()` for parent-aware styling
- Container queries (`@container`) for component-level responsiveness

### 17. User personas
- Base on real data (surveys, interviews, analytics)
- Include: name, age, goals, pain points, tech comfort, device
- Example for this repo: "María, 45, wants to lose 15kg, needs simple mobile workouts, low tech confidence"
- Use personas to guide: feature prioritization, copy tone, UI complexity

### 18. Security checklist
- HTTPS enforced (Vercel handles automatically)
- Helmet headers (`helmet()` middleware, CSP disabled intentionally)
- Input validation server-side (types, ranges, required fields)
- SQL parameterized queries (this repo: `pg` with `$1` placeholders)
- Passwords: hashed with PBKDF2 + salt, never logged
- Rate limiting on auth endpoints
- Cookie: HttpOnly + Secure + SameSite=Lax
- `.env` in `.gitignore`, secrets never committed

### 19. Social media integration
- Share buttons for exercises, progress, achievements
- Open Graph meta tags for link previews
- Instagram/TikTok-style before/after weight progress images
- Login with Google/Facebook (optional: OAuth libraries)
- Embed posts/timeline (lazy-load, non-blocking)
- Social icons in footer (SVG inline, accessible labels)

### 20. Current trends
- **Color:** Earthy greens, warm oranges (reflected in this repo)
- **Typography:** System font stack (Inter / system-ui), no web font loading
- **Layout:** Asymmetric grids, generous whitespace, card UIs
- **UI:** Micro-interactions (modal fade, button hover scale), minimal borders
- **UX:** Dark mode (CSS variables → `prefers-color-scheme`), glassmorphism cautiously
- Evaluate trend against: performance impact, accessibility, actual user value
